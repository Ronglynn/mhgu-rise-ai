### 技术要点
- HIRC 对象 size 语义为「含 id」（payload = size-4）；Event payload = u8 count + u32 actionID[]，字段**非 4 字节对齐**，扫描必须逐字节。
- 建图不可无向扫描：Sound/容器带 DirectParentID，会顺着父指针爬遍全库。容器只沿 children 列表（u32 count + u32[]）下行。
- media 文件名为 `*.bnk.2.x64` 双扩展名，glob 需 `*.bnk*`。

### 音质损耗实测（48k → GU 20k + DSP ADPCM）
- GU 音效实测为 **20000 Hz 单声道 16bit**（取自 `snd_slots/swo001_*.wav`），非推测。
- ADPCM 往返 SNR **23.64 dB**，波形相关 0.998。
- 48k 原始 **>10kHz 能量占 8.01%**，20k Nyquist 下必然丢弃；>5kHz 占 39.02%。
- 结论：**主要损失来自采样率，不是 ADPCM**。低频几乎无损，8k 以上金属锐度变钝。

## 重大进展：用 mod 差异反查目标音效（22:10）

### 方法（可复制，已实证）
下载「替换某个特定音效」的 mod（`.pak.patch` 内含完整 bank）→ 解包 → 与原版逐条比对 DIDX 的 size + 内容 MD5 → **size 剧变且新 hash 相同的条目即目标 wem**。
- 注意：Wwise 重编码会让数百条 wem 产生 ±几十字节差异，必须用「size 剧变 + 多条新 hash 一致」筛，否则全是噪声。
- 工具：`bin/analyze_mod_pak.py`（解包 + 比对 + 输出差异）。

- 对应 4 个 Event：`3543E7A1`、`918FFEDA`（共用 554722447）、`1A72E2A9`、`463567A6`
- 结构均为 Event → Action → RanSeqCntr(1 子) → Sound，无 Switch
- 时长：1.59s / 2.13s / 0.84s，48 kHz（前两条立体声，第三条单声道）

### 结论修正

## 3882 替换探针的结论 + Rise 音频 mod 的正确安装方式（23:29）

**已验证**：装 3882（`794051002` 被换成 PCM 16bit/2ch/48k/1.70s 人声）后，**有/无纳刀术 3 两种形态都播放人声**
→ 两种形态确实共用同一条 wem、同一个 Event（`509D5F88`）。静态推断得到实测确认。

**关键教训：Rise 的音频 bank 不能用散文件安装**。
- 散文件路径 `natives\STM\Sound\Wwise\` + `LooseFileLoader_Enabled=true`（在 `re2_fw_config.txt`，默认 false）
- 即使 `reframework_loose_files.txt` 记录到文件被访问、bank 版本(140)/bankID(0x4B625450)/DIDX 条目数全对，**声音依然不变**
- 原因：Wwise bank 加载不走 RE Engine 的 loose file 通道
- **正确做法**：用 `00_Tools/06_REEngine_Pak/ree-pak-cli.exe pack` 打成 `re_chunk_000.pak.patch_002.pak` 放游戏根目录，立刻生效
- 还原：删该 pak + 删 `natives` 目录，重启游戏（已执行，游戏目录已干净）
- `re2_fw_config.txt` 的 `LooseFileLoader_Enabled` 已置 true 并保留

**电平结论**：解析四条目标的 Sound 对象（Type 0x02，46 字节），`AkPropBundle` 里**无 Volume 覆盖**（全默认 0 dB）。
四条相对电平 = 素材电平：居合出刀 −1.1 / 特殊纳刀 −2.7 / 登龙 −8.7 / 大居合成功 −13.7 dBFS。
大居合成功轻 12 dB 是原始设计，**决定保持原样、不归一化**。

**794051002 的波形结构**：文件 1.78 s，但**有声只有 0~1.09 s**，后 0.69 s 是静音（非编码 padding，是素材自带）。
- 之前「1.79 s 动作 = 1.78 s 音效」的吻合是**文件长度**吻合，不是有声部分吻合（此结论已修正）
- 用户决定仍用 1.78 s 原长，不裁剪
