## 4 · P87② 否决论证（不再是「缺数据」）

1. 用户定义的输出窗口是**战斗内两招之间**的空档 `dE`；P85 已实测 GU `END→提交` 恒 1 帧，战斗内 `dE` 本就不存在。
2. 本场唯一的长空档（40 秒）是 **引擎行为层的换区进食链**：耐力归零 → 流口水 → `req=1` 换区 → `area` 2→5 → 进食恢复。玩家此时通常已不在同区，不是「留在原地给玩家输出」。
3. 抽选层在该窗口只有 5 次疲惫形状应用、2 次 `V.st3=2`，**FNV0 命中 0 次** ⇒ 「放开 FNV0 + 独立待机权重槽」没有施加对象，也造不出比原生 40 秒更长的战斗内窗口；强行加权只会让本已稀少的 5 次抽选更少。
4. 与 P88/P89 一致：疲惫侧「动作变慢」通道不通且方向相反，差异在行为层让位而非抽选层概率。

**定案**：`P87② 让位权重槽` **不立项**；不再为 A 安排实机。P90 探针已完成使命，其数据不足以支撑按怪分槽改版（改源码 ⇒ 重编译 + 实机 A/B，代价远大于收益）。
