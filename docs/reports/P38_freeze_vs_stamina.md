## 1 · 问题 1：是的，那是跑图/主怪离场，不是暂停冻结

**误差根源**：P37 把「连续 ≥8 条 R 行的 9 字段（`st/ex/thr/proc/amt/flg/t4/e1/dc`）全同」
直接命名为「冻结段」。但真正判暂停的判据是 P19/P22/P28/P30 定下的组合：
**`A_N`（动作开始总数）停止增长 + forge 帧继续涨 + R 行全同**。
我上一版只用了第三条，漏了最关键的第一条。

**补上 `A_N` 交叉核验**（本场 v50，主怪 `0C109CE0`，17 段全同段）：

| 段（f 范围） | 条数 | `ΔA_N` | 段内 A 行 | `low` | 判读 |
|---|---|---|---|---|---|
| 13650..13920 | 10 | **1** | 0 | 1 | 其它对象在动 |
| 14580..15000 | 15 | **3** | 0 | 1 | 其它对象在动 |
| 15090..15480 | 14 | **1** | 0 | 1 | 其它对象在动 |
| 20400..20640 | 9 | 0 | **1** | 1 | 有动作提交 |
| 20670..21030 | 13 | **4** | 0 | 1 | 其它对象在动 |
| 21540..21930 | 14 | **4** | 0 | 1 | 其它对象在动 |
| 22170..22410 | 9 | **3** | 0 | 1 | 其它对象在动 |
| 22530..23070 | 19 | **2** | **1** | 1 | 其它对象在动 |
| 33600..33900 | 11 | **5** | **1** | 1 | 其它对象在动 |
| **34500..36930** | **58（最长）** | **5** | **2** | **0** | **连低活动都不是，典型跑图/主怪离场** |
| 42450..44700 | 16 | 0 | 0 | 1 | 短暂无动作 |

汇总：全同段共 **9570 帧**，其中 **`A_N` 仍在增长的段合计 5580 帧 = 58.3%**
⇒ 游戏逻辑在这些段里正常运行，符合用户「除了跑图就在战斗、没有暂停」的描述。

**而且这与「不减气」结论无关**：主怪 `ex` 值域恒 `[0]`、`st` 在全程切换 10 次
（`{0:253, 1:303}`），**非全同段里 `ex` 同样是 0**。
P37 §3 的排除项 ④ 结论不变，只是理由从「冻结占比不够」改成
「静止段不是冻结，且 `ex=0` 与分段无关」。

> P37 已把「全同冻结段占比」改名「主怪状态静止段占比」并加注。
> 以后判暂停一律用 `A_N` 停止增长 + forge 帧继续涨，不能只看 R 行全同。

## 2 · 问题 2：方向完全正确，但要精修「盯哪个字段」

### 2.1 P20 的原始定案（用户直觉与项目结论一致）

`out/P20_stamina_chain_audit.md:56`：「因此前 7 轮一直在追『状态字 / 疲惫时长 /
函数入口』，而没有追 **『当前耐力值』这个轮询量**」；
`:69`：「共同问题：都在改『触发的输入』或『结果的标志』，没有改『被轮询的当前耐力值』」；
`:70`：Rise 网络包每个动作同步 `_Stamina`(U16/F32)，GU `0x816D0`(315 调用者) /
`0x8172C`(415 调用者) 支持每帧/每动作轮询当前值。

⇒ **是的，疲惫应该盯当前耐力/减气量的变化**，而不是盯状态字。
P29/P30 后来闭环的 `act+0x5D82 counter` 其实就是这条链上的「蓄积量」，
但它**不是当前耐力值本身**（P20:98 明确写了这点）。

### 2.2 三场实机对照：哪些候选真的在动

R 行从 v48 起就带 `s3f / f5c / p3ca / p3be / d5 / t5c / t4`，
但 P37 的分析漏看了它们。补上后：

| 字段（来源） | P30 跳狗龙（**有疲惫**） | v49 / 本场雄火龙（**无**） | 判定 |
|---|---|---|---|
| `s3f = rd8(*(mon+0xCAC0)+0x3F)` | **恒 0** | **恒 0** | P20 推荐的「状态字节」三场全不动，**不是当前耐力** |
| `f5c = rd(*(mon+0xCAC0)+0x5C)` | **恒 0** | **恒 1106247680 = 0x41F00000 = f32 30.0** | 恒定常量（雄火龙是固定 30.0），**不是被轮询的计时器/耐力** |
| `p3ca / p3be` (`act+0x3CA/+0x3BE`) | 各 11 / 18 个值 | 各 18 / 3 个值 | 两场都变、且会回升，更像坐标/角度类，**未定案** |
| **`ex`** (`+0x5D82` counter) | **0→25→90→0** | **恒 0** | 疲惫场活，雄火龙死 |
| **`thr / proc`** | 142→190→237→285 / 0→1→2→3 | 恒 233 / 恒 0 | 同上 |
| **`d5`** (`+0x5D88` 衰减计时器) | **35 个不同值** | **恒 0** | ★ 决定性，见 2.3 |
| **`t5c`** (`+0x5E0C` 状态计时器低16位) | **6 个不同值** | **恒 0** | 疲惫场活，雄火龙死 |
| `t4` (`+0x408`) | 恒 0 | 恒 65535 | 哨兵差异 |

**修正 P20 的字段建议**：`mon+0xCAC0 → +0x3F / +0x5C` 这组候选经三场实机
**不支持**作为当前耐力值（P20 当时自己标了 `[U]` 未验证）。
真正与疲惫联动的是 **`act+0x5D82 .. 0x5E0C` 这一整块**
（counter / thr / proc / 衰减计时器 / 状态计时器），
也就是 P29 定案的 Exhaust 运行期块。

### 2.3 决定性证据：`d5` 恒 0 ⇒ 从未有过有效减气量

P29 §2.2 定案：`0xA30E4 EXH add` 里
`counter += amount; 若 amount>=1 重置衰减计时器 act+0x5D88`。

- P30 疲惫场：`d5` 有 **35 个不同值**（`0, 16335, 16338, 16371, 16384, 32428, …`）
  ⇒ 反复有 `amount>=1` 的减气动作，计时器被重置并随时间衰减。
- 雄火龙两场：`d5` **恒 0**、`t5c` 恒 0、`ex` 恒 0、`proc` 恒 0
  ⇒ **整块 Exhaust 运行期区从未被写入**，不只是 counter 没涨。
  ⇒ 根因在更上游：**没有产生过 `amount>=1` 的减气量**
  （每动作减气点为 0，或 `0x9A470 → 0xA30E4` 通道对该怪根本没走）。

这比 P37 的「跨怪差异」更精确了一层：不是「耐力掉得慢」，
是**减气输入从未发生**。

## 3 · 修正后的因果链

```
动作参数(每动作减气点 stamina_point / StaminaSubRate)   ← 本场疑似为 0 或通道未走  ★
    ↓ 0x9DB54 / 0x9A470 取 amount = act+0x4D8
0xA30E4 EXH add: counter(act+0x5D82) += amount
    ├ amount>=1 → 重置衰减计时器 d5(act+0x5D88)   ← 本场 d5 恒 0，实证从未发生
    └ counter >= thr(act+0x5D84) → return 1        ← 本场 U=0，从未触发
    ↓ 0xA3198 grow: proc+1、thr 递推              ← 本场 proc 恒 0
虚表 +0x1CC → Stamina_low_Start / tired_start      ← 从未通知
```

`mon+0xCAC0 → +0x3F / +0x5C`（P20 路线 A 推荐的「当前耐力/状态」）在这条链的**旁边**，
三场实机看它不动，不参与本场的疲惫判定。
