用户问「W3 是出招门控吧」——**是，但更准确的表述是「动作未结束不重新抽选」的时机门控**。W1/W2 决定「抽哪一招」（权重形状、状态×距离档），W3 决定「什么时候允许重新抽选」，两者共同构成用户所说的「输出窗口」节奏。P34 阶段 D 原文：「在干净调用者层做『动作未结束不重抽』」，对标 Rise `_IsActionEnd` / `_IsUnderLayerEnd`。

**v68 已落地并部署**，且按用户约束「仅最大可能减少实机次数」设计：v68 = v67 + W3 门控，完整保留 AR 换区探针、B2、COMBO、BAND_SHAPE、stance。下一场本来就要为「疲惫→换区」链打，**同一场同时验 W3 门控与换区链，不增加任何实机轮次**；若门控不合适，编译期 `W3_GATE_ENABLE=0` 即回 v67（已有斩龙/轰龙两场基线），无需再打一场验证回退。

## 2 · 实现（6 hook 不变、零游戏内存写入）

**状态维护**（独立于所有日志配额，避免配额打满导致状态陈旧）：
- `h_unify @0x76154` 在 `(a3==2 && a1==0)` 时写 `END_F[slot]` 并递增 `END_N`（`ek`）。
- `h_start_40 @0xAFF40` 在动作开始时写 `START_F[slot]`。
- 两者另有全局兜底 `END_ANY_F / START_ANY_F`，应对 >8 个 mon 实例。

**门控判定** `w3_gate(mon)`：
```
IN_ACTION := START_F > END_F      // 最近动作开始晚于最近 action-end 请求
IN_ACTION 且 W3_GATE_ENABLE=1   ⇒ 拦下
否则                             ⇒ 放行
```

**作用范围严格限定在重抽路径**（`REP_N` 之后、`rise_weight_pick()` 之前）：
```rust
let (wp, wm0, wk0) = if w3_gate(a0) {
    rise_weight_pick(...)          // 套 Rise 形状
} else { (-1, 0u32, 0u32) };      // 自动落到 v38 原版权重轮盘
```
`wp=-1` 会自动进入既有 `else if sw2 > 0` 的 v38 轮盘 —— **抽选不中断、返回值语义不变、不写任何游戏内存**，只是该次不套 Rise 形状。

**不受门控影响**：`W1_ALL` 主轨全抽选（行 1943）、W2 `BAND_SHAPE`、W4 `stance`、AR/B2/COMBO/AE/QX 探针。因此即使门控拦下较多重抽，W2/W4 与换区数据仍完整。

**三重护栏**：
1. 编译期 `W3_GATE_ENABLE=0` ⇒ 完全回 v67 行为。
2. 自适应熔断：`GATE_SKIP > GATE_OK*4 && GATE_SKIP > 20` ⇒ `W3_AUTO_OFF=1`，之后全放行，防止 END 信号缺失时掐死整场重抽。
3. 拦下时退回 v38 原版权重而非丢弃抽选，动作链不会断裂。

**留痕**：S 行新增 `ge`（放行）/ `gs`（拦下）/ `ek`（END 事件数），累计不随 epoch 重置；判读脚本据此一场量化。
