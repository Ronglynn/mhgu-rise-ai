## 0 · 先给结论

| 问题 | 结论 |
|---|---|
| 纪律是否过度限制目标 | **部分是，但不是主要瓶颈**。三条「可放宽」确实压住了 L4/L6 之外的层；但 P72 §6 已定案「抽选层能复刻的 Rise **疲惫**逻辑已复刻完」，真正的天花板是 **Rise 侧资源未解包（L0/L1/L7）+ GU 引擎层差异**，不是纪律。 |

### 1.4 一条必须写清的澄清

**放宽「禁止按怪种编译表」≠ 放宽「禁止按单怪 action_id 硬编码」。** 二者常被混为一谈，但性质完全不同：

| | 被否决的 `v19b_action_ids.json` | 本次的 `dist_bands_rust.rs` |
|---|---|---|
| 数据来源 | 单场、单怪的日志白名单 | 137 个 enemy arc 的**全量离线**静态解包（P60） |
| 键 | 某一场观察到的 action_id | `emid = sp = rd16(mon+0xB5F0)`，137/137 对上权威槽表 |
| 是否写内存 / 改 arc | 不需要，但样本过拟合 | 不需要，纯 `.rodata` 常量 |
| 风险 | 换怪/换场即失效 | 换怪按 emid 自动索引，缺表降级 |

⇒ 纪律应精确化为「**禁止单场单怪样本过拟合**」，而不是「禁止按怪种」。这是本次审计最有价值的一条修正。

### 1.5 分类汇总

- **必须保留**：#1 零写入、#2 不整包重封 arc、#3 Hook 实机核对、#4 判据口径（+#10 顺带保留）。
- **可放宽**：#5 禁止按怪种编译表、#6 禁止查表、#7 只在抽选层 —— **放宽后仍保持零写入 / 不整包重封 / 6 hook / 不新增 hook**（本方案全部满足）。

## 2 · W2 路线 B 若放宽后的具体实现路径

> 以下是**「假如决定做」**的完整路径，不是本次实施内容。全程沿用现有 6 个 hook、零写入、不动 arc/bat。

### 2.1 编译期把 dttune 阈值表按怪种编进插件

产物 `out/dist_bands_rust.rs`（由 `tools/make_dist_bands_rust.py` 生成，可重复运行）：

- **键映射（已实证）**：`emid = sp = rd16(mon+0xB5F0)`。
  - 大怪 `emNNN_SS` → `(SS<<8)|NNN`（`monster-code-map.md §3`：`EmId=(variant<<8)|baseId`；`SS` 是 16 进制后缀）；
  - 小怪 `emsNNN_00` → `4096+NNN`（`dttune.md`「Small monsters」节）。
  - **校验**：对 `monster-slot-map-137.json` 的 137 个 emid 集合比对，**137/137 完全一致、无重复、无遗漏**（生成器内置校验，输出 `PASS`）。锚点：`sp=0020`→emid 32→轰龙（P66）、`sp=0050`→emid 80→斩龙（P67）均与映射吻合。
- **稀疏两级索引**（emid 值域 `0x0001..0x106A` 且稀疏）：`DIST_BAND_EMID: [u16;119]` 升序 + `DIST_BAND_START: [u16;120]` 行起点 + 扁平 `DIST_BAND_BITS: [[u32;4];330]`。稠密数组 `0x0000..0x106A` 会占 4203×16 B ≈ 65.7 KiB 且全是空洞，不用。
- **表示**：默认 `bits` = f32 的 **u32 位模式**（`f32::from_bits` 无损；`600.0 → 0x44160000`）；`--mode int` = **u16 整数化**（体积减半，最大四舍五入误差 **0.078125** 世界单位，1320 单元中仅 16 个非整数 f32）。
  - 需澄清：`f32` 与 `u32` 都占 4 B，**u32 位模式并不比 f32 字面量省二进制**，它的收益是值精确 / 源码短 / const 友好；真正减半靠 u16 整数化。
- **用 `static` 而非 `const`**：避免 const 在使用点内联把 5.6 KiB 表复制多份、且 `&CONST[..]` 不保证 `'static`；`static` 仍是编译期常量（无运行时初始化），只存 `.rodata` 一份。
- **数据噪声（必须在报告里说清）**：330 行来自「4 个递增 f32 + 2 字节对齐扫描 + 64 B 内聚类」（P60 §5），**不等于运行时语义 slot 数**：40 只怪含完全相同的重复行（如 `em001_00` row0==row2）、13 只 `candidateCount>=2` 聚类歧义、18 只无阈值行。行数不可直接当 slot 用。

### 2.2 运行时识别怪种 `sp`

- 现有 `lib.rs` 已在 V / COMBO / AR 行读 `sp = rd16(a0 + 0xB5F0)`（`:2276`、`:2367`、`:2580`、`:2607`），`h_matcher` 的 `a0` 即 mon 指针 —— **不需要新增 hook、不需要新字段**。
- 在距离块回调（`h_matcher`，`lib.rs:2074` 附近 `band_sense` 调用点）加 `let sp = rd16(mon + 0xB5F0);`。
- **护栏**：现有 `mon_ok` 只检查 `mon + 0x2600 < HEAP_HI`（`:1938`），覆盖不到 `+0xB5F0`；必须按 P61 的 `mon + 0x7700` 范式扩到 `mon + 0xB600 < HEAP_HI` 并 `heap_ok(mon)`，否则越界读。
- `sp` 未命中 `DIST_BAND_EMID` ⇒ `None` ⇒ 降级（含 18 只无阈值行怪、未知怪种）。换怪/换区时 `sp` 变化自然使旧档位失效。

### 2.3 用 ZP 几何距离定档

**现状先讲清**：`lib.rs:1960–1980` 的 `ZP` 行只把 `sub = rd(mon+0x1428)` 的 `+0x30/0x34/0x38/0x40/0x44/0x48/0x2E8/0x2F0/0x2F8` 与 `hd=rd16(+0x54)` 当 **u32 原始位** 打进日志，**插件内根本没有算过距离**，3D/XZ 距离是判读端 Python 离线算的（P60 §5、P61 §3.2）。路线 B 要把这段搬进插件：

1. 从 `sub` 几何字段解出怪与目标的两个坐标三元组（f32 位 → 值）。
2. 定 `d`：3D `sqrt(dx²+dy²+dz²)` 或 XZ `sqrt(dx²+dz²)`；**用哪一种尚未定案**（P60 §5 只说「几何字段在 sub+0x30..0x48 / +0x2E8.. / +0x54」）。
3. 按 `dist_band_for(sp, slot, d)`：`d<=t0→0`、`<=t1→1`、`<=t2→2`、`<=t3→3`、否则 `4`（P61 §3.1：4 个递增阈值天然切成 5 区间 ↔ Rise 5 档；该对应是 `emc.md` 顺序比较语义的**推断，未实机验证**，P61 §5）。**§4.5 已追加实证**：所谓「Rise 5 档」是 15 池 `range1..range5` 的池索引，`range_data` 里没有对应几何阈值，因此这一步的「↔ Rise 5 档」只是命名巧合，**不能作为对齐依据**。
4. `slot` 选哪一行：**未定案**。`0x71164(ctx,slot)` 无逐条反汇编；`beginArgs` 值域 `{0,1}` 被离线结构性反证无法编码每怪 2–6 行（P61 §1）；`case.sig` 静态哈希只能证明「结构表运行时可用」，补不出语义标签（P72 §6）；`ZT=0` 又断掉了运行时表链（P64 §4.2）。⇒ 只能先用 `slot=0` 或按 `hit` 反推，**这是路线 B 最大的正确性缺口**。
5. **软浮点风险**：`armv7a-none-eabi.json` 是 `llvm-floatabi: soft`，当前插件几乎没有 f32 运算；引入 `f32::from_bits` / 比较 / `sqrt` 会首次拉入 `__aeabi_*` 软浮点 helper，`.text` 额外增长。规避方案：编译期把阈值**预算成平方 u32**，运行时把坐标整数化后算整数 `d²` 再比较，全程整数运算（非负 f32 的位模式按 u32 单调，也可直接比位模式）。

### 2.4 护栏与降级（多级，任一级失败都不中断抽选）

| 级 | 条件 | 动作 |
|---|---|---|

### 3.2 「编译进 64 KB NRO」是否可行 —— 精确结论

`bin/elf2nro.py`：`total = Σ align_up(PT_LOAD[i].filesz, 0x1000)`，**无 64 K 硬上限**，按页增长。解析当前部署 `out/rai_log_integrity_v71.nro`（65536 B = 16 页）：

| 段 | 范围 | 分配 | 实际内容 | 余量 |
|---|---|---|---|---|
| seg0 `.text` | `0x0..0xB000` | 45056 B（11 页） | 44968 B | **88 B** |
| seg1 `.rodata` | `0xB000..0xF000` | 16384 B（4 页） | 14776 B | **1608 B** |
| seg2 `.data` | `0xF000..0x10000` | 4096 B（1 页） | 2477 B | 1619 B |

最后非零字节 63916 ⇒ 实际内容 63917 B；距 65536 余 1619 B，但**分散在三个段里，单张表只能用 `.rodata` 的 1608 B**。

| 方案 | rodata 增量 | 新 rodata 对齐 | 新 NRO 总长 | ≤64 KiB? |
|---|---|---|---|---|
| `bits` 全表 5758 B | 14776+5758=20534 | 24576（6 页） | 45056+24576+4096 = **73728 B（18 页）** | ❌ 超 8192 B |
| `int` 全表 3118 B | 14776+3118=17894 | 20480（5 页） | 45056+20480+4096 = **69632 B（17 页）** | ❌ 超 4096 B |
| 每怪首行+`int` 1430 B | 14776+1430=16206 ≤16384 | 16384（4 页） | 65536 B（16 页） | ✅ **仅数据**能塞下 |

**但代码会破局**：路线 B 必须新增查表 + 几何解释 + `sqrt`/比较（≥数百字节），而 `.text` 只剩 **88 B**，任何 >88 B 的 `.text` 增长都会把 seg0 从 11 页推到 12 页 ⇒ 总长至少 69632 B（17 页）。

⇒ **结论**：
1. **当前 v71 全量探针版：不可行**（代码 + 数据合计必破 64 KiB，最小都要 68 KiB）。
2. **成品版可能可行但未验证**：P72 §2 的 `lib.rs.release` 关掉探针（`W2_PROBE=0`、`MAX_B2/MAX_AE/MAX_COMBO/MAX_AR=0`），107 个 `info!`（每行 270 字符格式串）会释放大量 `.rodata`，但**未编译、未部署**（P76 §4.4 由另一路负责），需实测才能定。
3. **「64 KB NRO」本身不是已证实的硬上限**：`elf2nro.py` 无此限制，Forge loader 是否接受 >64 KiB NRO **从未验证**。这与本报告主题一致 —— 它又是一条「自定约束」，只是证据等级比 #1/#2 低得多。
