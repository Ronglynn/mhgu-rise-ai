### 1.2 一次性有界强制疲惫 —— **本项目首次游戏内存写入**

```
wr16(act + 0x508, 0)    // 当前耐力归零，模拟耗尽
wr8 (act + 0x505, 2)    // 疲惫状态字=2，使 0x816D0 立即返回 1
```

只写 **3 字节**、只做 **1 次**。依据 P46 链 I：
`0x816D0 = ((+0x505 & 0xFE)==2)` → `0xF8D384` 在 `[p+0x41]==0` 时写 `p+0x41=5`
→ 播放 `Stamina_low_Start`。写 `+0x508=0` 同时让当前耐力与疲惫态自洽，
避免 `0x76340`（`+0x505==3 && +0x508!=0` 时复位）立即撤销状态。

## 4 · 已知边界（必须说清）

1. **这是游戏内存写入，不再是纯只读插件**。虽然只有 3 字节、一次、有熔断、可即时回退，
   仍存在状态机不同步、动作异常、任务内行为异常的可能。若异常，立即关游戏并覆盖回 v53。
2. **强制 ≠ 游戏原生链路**：它直接置位 `+0x505=2`，跳过了 `0xBD260` 的耗尽判定与
   `0x76154` 的 1→2 门控。目的是制造一次可记录的疲惫窗口，不是复刻完整触发链。
   若要让游戏自己走完链 I，需 hook `0xBD260` 放大 delta（新增 hook，须核对 IPS32 首字）。
3. **W1 疲惫形状可能不触发**：v49 三态层的疲惫判据基于链 II（`EXH ret==1` / `proc` 递增），
   而强制疲惫走链 I。因此本场 `st3=2` / `wm=3` / `wt>0` 很可能全 0 —— 判读脚本已将其
   标为 SKIP 而非 FAIL。**把疲惫判据切到 `t505>=2 || p41>=5` 是 v55 的明确待办**，
   这也是「尽可能复刻 Rise」路线上一个实质缺口。
4. `LOW==0` 门控在长时间跑图/挂机时可能延后或阻止触发；需怪实际活跃。
5. 尚未实机；所有结论止于编译 + 冒烟 + 三代真实日志降级。
6. P33 的 `c0000005` 仍未归因；本版新增写入面，若复现应立即回退并单独排查。
