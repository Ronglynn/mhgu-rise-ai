## 6 · 18:10 追加澄清：用户质疑「不能按 Rise 逻辑做吗」

只读复核 Rise 侧资产后，§0 的「正式列为不可复刻项」表述**下过头了**，更正如下。

**「按 Rise 抽选层逻辑做」其实已经做完**：W1 疲惫形状 `[60,30,10]` 就是 Rise tired 池实测低熵形状的熵拟合（P34/P57），W2 疲惫档位形状、W4 疲惫处境也都在。P70 实测结果是没有喘息（10.5→12.4 每千帧）。**原因不是没复刻，而是 Rise 的抽选层逻辑本身不产生喘息**：

| Rise tired 池证据 | 值 / 出处 |
|---|---|
| 候选数 | 5 张全是 **3 个候选**（anger/normal 多为 4）`rise_band_shapes.json` |
| 首项权重 | **45~70%**（tired_range1 `[65,25,10]`、range5 `[70,20,10]`） |
| 平均熵 | **1.2984** vs anger 1.6740 / normal 1.6669（低 22%）`P32:89-93` |
| 显式冷却字段 | `explicit_cooldown_field_found = False` `rise_ai_rules.json:441` |
| 率和 | 恒 100 ⇒ 每次抽选仍命中一个动作，只是更常落到同一张表 |

⇒ 低熵 = **出招更单一 / 复读感更强**，不是「动作更少」。早期 `DESIGN_v16:64-65`「疲惫池偏向低威胁表 ⇒ 输出窗口变长」的叙事已被 `P32:15,134-135` 判定箭头配对错误并降级（表 51 常态也高权重）。

**Rise 真正的流口水 / 输出窗口在抽选层之外**：
- 引擎状态层：`_IsTired` 持续布尔 + `_tiredSec` / `_hyakuryuTiredSec` / `_AddTiredTime` + `EnemyStaminaManager`（`P32:112-118`、`P20`），但 `emNNN_00_stamina_data.user.2` **未解包**，疲惫时长与 `_motRate` 无实例数值（`P32:166-167`）。
- 逐动作层：`ActionInfo._tiredMotSpeedLowerLimitValue`（疲惫动作速度下限），3 个 `action_param_data` 实例里仅 16/16/10 个动作显式设 1.0，其余 -1.0；无反汇编/Rise 实机证明它拉长硬直。
- 动作资源层：`action/ combo/ motion/ message/ actiontune` 类文件**全部未解包**（`P32:168-171`「442 条清单 437 条 0 覆盖」）⇒ 是否存在专属疲惫待机动作，工程内**未知**，不能证伪也不能定量。
- 12 个 `attack_stance_*` Hub、15 池、全 107 个 rsz_json 搜 `tired/drool/rest/fatigue/待机/喘` **0 命中**（除文件名）。
- `P32:201`：全部 Rise 侧结论都是**静态资产复核，无 Rise 实机或反汇编**。

**GU 侧对应也在状态机层**：`Stamina_low_Start / tired_start / tired_Loop` FSM（`P29:112` 反汇编字节级）、疲惫是瞬时事件无持续状态字（`P29/P30` 反汇编 + MHGU 实机）。本项目 6 个 hook 全在抽选 / 动作开始层，**够不到 FSM 与动画时长**。

**修正后的定案**：在「零游戏内存写入 + 跨怪通用 + 不按 action_id 硬编码 + 6 hook 全在抽选层」四条现有纪律下，抽选层能复刻的 Rise 疲惫逻辑**已经复刻完**；「喘息」属于引擎 / 动画层，需要写内存或改资源，且连 Rise 实例数值都未解包 ⇒ **当前不可定量复刻**。若放宽纪律（例如 v55 范式 hook 动作速度 setter 只改入参）或补齐 Rise 动作资源解包，仍有可能 —— 不作无期限排除，但也不再为它单独安排实机轮次。

**一个仍可零成本试的选项**（不增加实机轮次、并进下一场即可）：疲惫态 `eff==ST_TIRED` 时**不套 Rise 低熵形状、退回 v38 原版权重**（编译期开关 + 统计），用于排除「W1 低熵形状造成复读/密集」这一嫌疑。P70 中 `wt=7` 表明疲惫形状只应用 7 次，主因大概率仍是 GU 原生节奏，故本项**默认不做**，等用户决定。

补充一个此前容易混淆的口径：`case.sig` 是 case 分支体内前 16 个 `op0x14` 操作数的 FNV-1a（`lib.rs:1443-1489`），静态可复算（`audit_emc_caseoff.mjs` 已离线对拍 137 arc / 141792 case），**P60 的「单基址最多覆盖 1/11 ip」只阻断按 ip 查物理阈值表，不阻断按 sig 内容哈希查表**。但这只说明「结构表运行时可用」，补不出语义标签。
