## 4 · 新发现：`0x9A468` 的 amount 门控（离线字节级）

按 base=0 反汇编 `refs/hpbar/main_text_decomp.bin`：

```
0x9A454  E30004D8  movw r0,#0x4D8
0x9A460  E19710F0  ldrh r1,[r7,r0]      ; r1 = act+0x4D8 (amount)
0x9A464  E3510001  cmp   r1,#1
0x9A468  BA000007  blt   0x9A48C        ; ★ amount < 1 直接跳过 EXH add
0x9A46C  E1A00004  mov   r0,r4
0x9A470  EB00231B  bl    0xA30E4        ; 仅 amount>=1 才调用
0x9A48C  E30004DA  movw  r0,#0x4DA      ; 下一个状态块
```

⇒ **`gac=0` 有了精确解释**：不是「hook 没装」、不是模糊的「路径差异」，
而是 `0x9A34C` 状态更新总入口读到 `act+0x4D8` 时，该值**从未 ≥ 1**，
`blt` 直接跳过了 `0xA30E4`。断点因此前移到 **`0x9DBE4` 的累加环节**
（每动作把减气点 `r3` 加到 `act+0x4D8`），而不是 EXH add 本身。

结合 Y 行 200 条 `am=0` 与每帧 8 槽全量统计 `anf=0`：
`act+0x4D8` 在所有可采样时刻都是 0。仍不能排除「写入-清零窗口短于采样间隔」
（P43 已如此裁定），但**「`0x9DBE4` 未累加」与「累加后瞬时清零」**这两种解释
现在可以由下一版 hook 直接区分。

**推断（未定案）**：GU 的发怒 / 减气链可能需要玩家与怪交互（造成伤害）。

不足以让雄火龙减气。所以更可能是**两因素叠加**：本场未触发交互 +
雄火龙自身的减气数据层问题（P37/P38 已记录）。
