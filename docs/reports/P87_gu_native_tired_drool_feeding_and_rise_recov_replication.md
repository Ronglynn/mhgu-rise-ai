## 0 · 结论先行

1. **两条都能找出，而且指向同一层**：GU 的「流口水」与「换区进食」都是**引擎层原生疲惫链 I** 的产物，不是插件需要生成的东西。`dE`（两招间隔空档）为 1 帧，不等于「GU 没有喘息」，而是「喘息不在抽选层、在 FSM / 动画 / 换区层」。

4. **不推翻 P85**：`_motRate` 动作速度通道仍不通（GU 无疲惫专属速度槽、`≥1.0` 钳制），这是**另一条通道**。P85 关于「不能靠搬倍率产生 `dE`」的结论全部维持。
5. **可落地路径**：不造间隔、不搬倍率，而是**按 Rise 进食恢复曲线让抽选层「让位」给 GU 原生流口水待机 / 换区进食**（P86 的 `sig==FNV0` 结构偏转 + Rise 阈值门控）。仍在四条纪律内、不新增 hook、零写入、跨怪通用，但**当前是推断级，必须先做纯只读探针**。
6. **没有可直接部署的成果**：v2 成品行为、P79 验收、P80/P83/P85/P86 结论全部不变。

全 78 怪字段分布：

| 字段 | 分布 | 语义 |
| --- | --- | --- |
| `_SetMeatRecovStartPoint` | **20.0（56）/ 30.0（22）** | 耐力降到该百分比 ⇒ 开始找肉 / 进入恢复流程 |

| `_SetMeatEatSec` | 10.0（56）/ 15.0（22） | 放置肉（陷阱肉）进食时长 |
| `_SetMeatConditionSec` | **5.0（78/78）** | 进食条件等待 |
| `_InCombatMapMeatEatFlag` | **False（78/78）** | **战斗中不吃地图肉 ⇒ 必须脱战 / 换区** |
| `_IsEnableSetMeatEat` | False（65）/ True（13） | 13 怪允许战斗中用放置肉 |
| `_SetMeatCombatList` 长度 | 0（65）/ 1（13） | 与上对应 |
| `NikuEatInfo._Probability` | 30.0（58）/ 25.0（2）；`_Stamina` 0.0（60） | 地图肉触发概率 |
| `SetMeatInfo` | `_StaminaRate` 0.0(21)/50.0(16)、`_CheckTime` 15/30、`_Distance` 60/30、`_Rate` 100/30 | 恢复量 / 检测间隔 / 触发距离 |
| `_motRate` | 0.8~1.0（7 种，60/78 非 1） | 动作播放速度（P85：只改 `dS`） |
| `_tiredSec` | 0~120 s（12 种，61/78 非 0） | 状态持续（P80） |

**语义链**：`ActionInfo._subStaminaPoint` 每动作扣耐力 → `_IsTired` + tired 五池换表（抽选层，v2 已复刻权重形状）→ 脱战/换区后按 `_SetMeatRecovStartPoint` 触发找肉 → 进食 `_mapNikuEatSec`/`_SetMeatEatSec` 秒 → 耐力回到 `_SetMeatRecovEndPoint` → 疲惫结束。**「换区必定进食」不是玩家错觉，是 `_InCombatMapMeatEatFlag=False` + `_SetMeatCombatList` 65 怪为空的必然结果。**

**对 P86 的精确修正**：P86 §1「引擎/动画层本项目静态资产无法定量（442 条动作资源清单 437 条 0 覆盖、`tired/drool/rest` 0 命中）」——**动画资源与流口水演出仍无法定量，但进食恢复的参数链完备**。P32 §4 早已写「恢复：部分对应（都指向进食）」，当时判为「不等价」的表项之一，本轮升级为**两作之间唯一同构、且首次可定量的复刻落点**。

### 4.2 三阶段

**① 纯只读探针（可并进下一场自然任务）**
按疲惫态 / 非疲惫态分别统计：`FNV0` 命中次数、命中后到下一动作开始的帧差分布、该段 `+0x508/+0x506` 百分比、`dc`、`t505`、`area/req`、段内动作数。**判据**：是否存在「耐力 ≤20~30% + 换区/脱战」重合、且持续 ≥300 帧的低动作段；若有，其长度分布与 Rise 的 20 s 是否同量级。同时排除 P79 的「换区赶路 / 主怪离场」伪空档（用 `area` 变化 + 主怪是否仍在场 + BEAT 全量交叉）。

**② 编译期开关（仅在①成立时）**
门控：`(t505>=2 || dc==1) && (cur*100/max) <= StartPoint(20或30) && (换区 hub3 / 无目标 hub1)`。
动作：放开 `rise_weight_pick` 的 FNV0 排除、给 FNV0 独立权重槽（或该处境直接不改写 `ret` 让原版待机保留），并为 FNV0 单独处理 `prev_hit_d` 判重、限制每场次数与两次待机最短间隔，防原地发呆。
撤销：`(cur*100/max) >= EndPoint(70或80)` 或离开该处境。
护栏 / 评估基准：`_mapNikuEatSec=20s` / `_SetMeatEatSec=10~15s` / `_SetMeatConditionSec=5s` —— **只作目标与上限，不硬塞给 GU**（GU 进食动画时长由引擎 FSM 决定）。
其余：`W1_ALL` / `W4_HUB_ENABLE` / `DRAIN_ENABLE` 不动，保留一键回退。

**③ 跨怪 ≥2 种 A/B**
判据改为「低/零动作段帧数、占战斗时长、玩家可攻击段」，**不用 `dE` / `gap`**；核对零 FATAL、无发呆/吼叫/动画错位、正常结算。改动后 P79 验收不再自动适用。

### 4.3 与既有结论的关系

- **不推翻 P85**：本路径不产生「两招之间更长的 `dE`」，而是让原生待机/进食状态出现；P85 关于 `dE` 不存在、Rise 无间隔倍率、`_motRate` 通道不通的全部定案维持。

- **达成度口径不变**：这是「疲惫输出窗口」这条未闭环项下的新子路径，不改变 L0 舍弃、适用 5 层 1 达成/3 近似/1 证伪的结论。
