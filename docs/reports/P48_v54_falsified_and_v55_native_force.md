## 2 · 静态定因（`main_text_decomp.bin`，base=0，capstone 复核）

`0xBD260(mon, delta, max)` 是每动作扣当前耐力的唯一入口（caller `0x75768`）：

```
0xBD2A8 movw r0,#0x508
0xBD2AC rsb  r3, r5, #0          ; r3 = -delta
0xBD2B0 ldrh r2,[r1,r0]!         ; r2 = cur = +0x508
0xBD2B4 cmp  r2, r3
0xBD2B8 ble  0xBD350             ; ★ cur <= -delta ⇒ 耗尽分支
0xBD2BC add  r3,r2,r5            ; 否则 cur += delta
0xBD2C4 strh r3,[r1]             ; ★ 回写 +0x508
0xBD2D8 strhhi r6,[r1]           ; ★ clamp 到 max
...
0xBD2EC..0xBD30C  strb r2,[r1,#0x505]   ; ★ 每次调用重写 +0x505（0 或 3）
0xBD350 mov r0,#0 / strh r0,[r1]         ; 耗尽 → +0x508=0
0xBD35C bl 0x816D0 / 0xBD370 bl 0xA1FC8(mon,0x20) 门控
0xBD390 strb r1,[r0,#0x505]              ; 门控通过 → 写 1
```

后续 `0x76154` 内 `0x762C8..0x76358`：
```
0x762C8 ldrb r1,[act,#0x505] ; cmp #1 / bne skip
0x762E0 bl 0x8172C           ; 要求「不发怒」
0x762F4 bl 0x7FC08(mon,4) / 0x76304 bl 0x81774 /
0x76318 bl 0x7FC08(mon,0x10) / 0x76328 bl 0x81790   ; 四重位门控
0x76338 mov r1,#2 ; 0x76358 bl 0xBD184  ; ★ 1→2
```
再 `0x816D0`：`(+0x505 & 0xFE)==2` → 1 → `0xF8D384` `[p+0x41]==0` → `strb #5`
→ `Stamina_low_Start`。

**结论**：`+0x505` 不是可直接置位的状态字，而是由 `0xBD260` 的耗尽判定
与 `0x76154` 的门控共同推进的派生状态。要强制疲惫，**必须让游戏自己扣光耐力**。

### 附带实证（P46 静态推断首次实机确认）

`act+0x508` 确为**当前耐力值**：`t506` 恒 1000（上限），`t508` 从 626 /
写 0 → 游戏拉回 800 → 随动作缓降到 618。此前 P46 只由静态推断，本场首次读到活值。

## 3 · 两个附带缺陷

### 3.1 `0xBD260` 为何把 0 拉回 800

`0xBD2BC add r3,r2,r5` + `0xBD2C4 strh` + `0xBD2D8 strhhi r6`：
游戏以 `delta`（可为正的恢复量）与 `max` 持续维护 `+0x508`，
外部写 0 只是一次无效扰动。**具体恢复来源（进食/状态机重置）未定案**。

### 3.2 R 行 270 字符截断（工具缺陷）

647 条 R 行长度**全部恰为 270**，主怪行被切在 `t508=... t50`：
`p41 / pt5c / t1a8 / t362 / t5df3 / low / log` 全部丢失；
`p41=` 只在字段值较短的小怪槽出现（428/647）。
⇒ v54 的「完整链 I 快照」实际**没落盘**，判读的 1 个 FAIL 源于此，不是插件错误。

## 6 · 边界（必须说清）

1. **v55 尚未实机**。第 6 个 hook 只做了静态首字比对 + 运行时条件安装，
   未实机核对 `0xBD260` 的运行时首字；若为 IPS32 跳板会自动 SKIP（日志写明），
   此时**没有任何强制**，只剩纯只读观测。
2. **原生链路仍有门控风险**：`0xBD370 bl 0xA1FC8(mon,0x20)` 与 `0x762F4..0x76328`
   四重位门控若不满足，游戏可能只写到 `+0x505=1` 或被清回 0，不见疲惫动画。
   这是**游戏自己的判定**，插件不能绕过（绕过就等于回到 v54 的证伪方案）。
3. **`+0x508` 恢复来源未定案**（§3.1）；`0xF8D384` 的 `arg0` 是否等于插件 `mon` 仍未实机验证（P46 [U]）。
4. 本场 v54 日志的疲惫窗口 `p41` 因截断缺失，无法回答「v54 强制时 FSM 是否推进」；
   v55 的 W 行专门修这个。
5. P33 的 `c0000005` 仍未归因；本场零 FATAL / 零 `c0000005`。
