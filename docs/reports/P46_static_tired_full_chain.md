## 0 · 结论先行

1. **找到了 P20 一直没定位到的「被轮询的当前耐力值」：`act+0x508`（u16，初始 0x3E8 = 1000），上限 `act+0x506`。** `act = *(mon+0x1428)`。
2. **疲惫状态字是 `act+0x505`（u8，值 0/1/2/3）**，与发怒标志 `act+0x518`、减气 counter `act+0x5D82` 是**三个互不相关的字段**。
3. **存在两条数据流完全并行的链**：链 I（耐力主链，`+0x508 → +0x505 → 动画 FSM`）与链 II（P29 减气蓄积链，`+0x4D8 → +0x5D82 → grow → 虚表`）。P29 那条**不写 `+0x505`**，二者只在控制流主干 `0x76154 → 0x755b4` 上共享宿主、走不同 case。
4. ⇒ **P45「雄火龙疲惫但 `0xA30E4` 整场 0 次」被完全解释**：疲惫走链 I；链 II 因 `act+0x4D8 < 1` 被 `0x9A468 blt` 跳过。**「无发怒却疲惫」也被解释**：1→2 推进的门控明确要求 `0x8172c(mon)==0`（不发怒）。
5. **P45 的「解释 A（另一条路径）」现由静态实证定案**，解释 B（用户看到的不是疲惫）不再是必需假设。

## 1 · 链 I：耐力主链（真正的疲惫触发链）

### 1.1 分层时序（全部 base=0，capstone 复核）

```
[L0] 动作开始：0x76154(mon, id, sub, arg3)   [17 个 BL caller]
      ├ 门控：mon+0x73E0 != 0xB；动作 id 位掩码 0x3DF00 命中；arg3 ∈ {0,5}
      └ 0x768EC bl 0x755B4(mon, id, sub)

[L1] 0x755B4 内查表取「本动作减气点」
      0x756A8 bl 0x711E8 → [r0+8] 表 → 逐项匹配 (id, sub)
      → 0x75740 ldrsh r0,[r5]        ; short = 动作减气量 delta
      → 0x75754 vmul.f32 s0,s0,s2   ; × 倍率（mon+0xB720 或 1.0）
      → 0x7575C ldrh r2,[act+0x506] ; 上限
      → 0x75768 bl 0xBD260(mon, delta, max)      ★ 唯一 BL caller

[L2] 0xBD260 扣减当前耐力 / 判定耗尽
      总闸门：0xBD284 ldr r0,[act+0x1A8] ; and r0,r0,r8(0x80001) ; cmp r0,#1
      0xBD298 bl 0x711E8 → 非 0
      0xBD2A8 movw r0,#0x508 ; 0xBD2B0 ldrh r2,[act+0x508]!   ; cur = 当前耐力
      0xBD2AC rsb r3,r5,#0  → r3 = -delta
      0xBD2B4 cmp r2,r3 ; ble 0xBD350                          ; cur <= -delta ⇒ 耗尽
      未耗尽：0xBD2BC add r3,r2,r5 ; 0xBD2C4 strh r3,[act+0x508]   ; 累加（delta 可正可负）
              clamp 到 max(act+0x506)
      耗尽：  0xBD354 strh #0,[act+0x508]                        ; 清零
              0xBD35C bl 0x816D0 ; 未疲惫才继续
              0xBD370 bl 0xA1FC8(r1=0x20) → (act+0x5E08 & 0x20)==0 才继续
              0xBD380 (act+0x1A8 & 0x80001)==1
              0xBD390 strb r1,[act+0x505]                        ; ★ 写 1（耐力耗尽中间态）

[L3] 0x76154 内把 1 → 2（正式疲惫）
      0x762C8 ldrb r1,[act+0x505] ; cmp r1,#1 ; bne 0x7635C     ; 必须 ==1
      0x762E0 bl 0x8172C ; bne 0x7635C                           ; ★ 发怒则跳过
      0x762F4 bl 0x7FC08(r1=4)   → (act+0x362 & 4)==0
      0x76304 bl 0x81774          → act+0x518 != 2
      0x76318 bl 0x7FC08(r1=0x10)→ (act+0x362 & 0x10)==0
      0x76328 bl 0x81790          → act+0x5DF3 == 0
      0x76338 mov r1,#2 ; 0x76358 bl 0xBD184(mon, 2)
      → 0xBD1B0 strb r1,[act+0x505]                              ; ★ 写 2

[L4] 疲惫读取 / 动画 FSM
      0x816D0 (8 ins / 315 callers)：ldrb r0,[act+0x505] ; and r1,r0,#0xFE ; cmp r1,#2
              ⇒ (val & 0xFE)==2 → 1  【值 2 与 3 都算疲惫】
      0xF8D384：p = *(mon+0xCAC0)
              [p+0x41]==0 && 0x816D0(mon)==1  → 0xF8D710 strb #5,[p+0x41]
              → 播放 Stamina_low_Start；状态循环 0→5→4→6→0（Start/End 各带动作计时器）
              计时器在二级解引用 [[p+0x30]+0x5C]（疲惫）/ [[p+0x34]+0x5C]（发怒）

[L5] 结束 / 恢复
      0xBD3D4..0xBD3E4：0x816D0!=1 且 +0x505==1 → 清 0
      0x76340：+0x505==3 且 act+0x508 != 0 → 0xBD184(mon, 0)
      Stamina_low_End 条件 0x816D0(mon)==0；恢复靠进食 / 耐力回升
```

## 2 · 链 II：P29 减气蓄积链（并行，非疲惫唯一入口）

```
0x9DB54 → 0x9DBE4  movw r1,#0x4D8 / ldrh / add r1,r1,r3 / strh   ; 每动作累加到 act+0x4D8
0xADE48 (mon+0x7648==0) → 0xA5900 (mon+0x61A0==0) → 0x97DDC
   → 8 部位循环结束 → 0x98A60 bl 0x9A34C（每帧 1 次，不是每动作）
0x9A454 movw r0,#0x4D8 ; 0x9A460 ldrsh r1,[act,r0]
0x9A464 cmp r1,#1 ; 0x9A468 blt 0x9A48C         ; ★ amount<1 直接跳过
0x9A470 bl 0xA30E4(mon, amount)
   counter(act+0x5D82) += amount ; >= thr(0x5D84) && [vt+0x39C]()!=1 → ret 1
0xA3198 grow（唯一 caller 0x75F0C，在 0x755B4 内）→ 0xA325C b 0xA4130
   → 0xA414C ldr r3,[vt+0x1CC] ; mov r1,#9 ; bx r3  → Stamina_low_Start / tired_start
```

**并行性实证**：`0x9A34C..0xA47B8` 全段**无一处** `+0x505` 访问，BL 目标中无 `0xBD184/0xBD260/0x816D0`；两链写入字段集合零交集，唯一共享是只读 getter `0xA1FC8`（读 `act+0x5E08`）。控制流上共用 `0x76154 → 0x755B4`，但链 I 走 `0x75768 bl 0xBD260`，链 II 走 `0x75F0C bl 0xA3198` 的不同 case。

## 6 · 边界与存疑

- 全部结论为**静态反汇编实证**；`act+0x508` 的「当前耐力」语义由
  `0xBD2B0 读 / 0xBD2C4 写 / 0xBD354 清零 / 初始 1000 / clamp 到 +0x506` 推断，
  尚未实机读值验证。
- `0xF8D384` 的 `r8 = arg0` 是否等于插件里的 `mon`，P20 标 [U]，本轮仍存疑（静态无法定案对象同一性）。
- `+0x505 == 2` 与 `==3` 在 `0x816D0` 中不可区分（`(val&0xFE)==2` 对 2、3 同真）；
  差异只体现在下游 `0x762CC/0x82A3C/0xC8F5C/0xCB6A8` 的显式 `cmp #3`/`cmp #2`，语义差别存疑。
- `0x711E8` 返回的 `[r0+8]` 表被推断为「(动作 id, sub) → 减气量 short」；
  表名与偏移未在文档中定案。
- 链 D（`0xCC154` 外部状态包）与链 E（`0x72128` 计时器）在生成/载入期或特定条件下触发，
  是否参与战斗中的自然疲惫未定案。
- `0x1068DD8` 链实机 T=0 只证明「该场/该怪/该变体」未调用，不能推出全二进制永不调用。
- P33 的 `c0000005` 仍未归因；本轮未触碰游戏与部署。
