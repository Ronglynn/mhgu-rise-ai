### 2.2 不支持 / 未确证（静态，代码级）

`06_MH4UPort_IPS32/.../notes/area-move.md` 定案：

- 换区条件 BLOCK：`0x3f` = `this+0x73f3 != 0`（请求位）、`0x54` = `+0x73f4`（set up）、`0x61` = `+0x73f0`（running）、`0x07` = 当前区域 `this+0x1054`。
- 执行体是 EMC **leaf** 命令 `0x94`(setup→`0x8f004`) / `0x95`(start→`0x8a690`) / `0x9e`(advance→`0x8d418`)，最终 `0xb5d6c` 转移并由 `0xb5e04` 写 `+0x1054`。
- **`+0x73f3` 的写入者未找到**（文档标 G），推测由「区域停留计时器 0xb8044、`+0x73fc` reset 1800、按地图数据 `+0x7624` 掷骰」驱动。
- **疲惫状态字 `+0x505` 不是换区的代码级直接条件**。

因此两者可能是：① 疲惫 → 触发离场休息/进食 → 间接置请求位；② 疲惫与区域停留计时器到期恰好同时（时间相关非因果）。**当前探针无法区分**。

### 2.3 跨怪辅助（雷狼龙 v56 归档场）

疲惫窗 f=9150..12600，A 行动作间隔 p50：PRE 282 → TIRED 309 → POST 289 帧，变化不显著；该场是 ×64 强制疲惫、且无 ZP 几何探针，粒度不同 ⇒ **不支持也不否定**，只能说明「间隔拉大」不是跨怪稳定特征。

### 2.4 若成立的工程意义（潜在翻案）

P36 曾判「强制换区不可行」，主要理由是执行体是 leaf 命令、没有可在 `h_matcher` 改的 case 分支，且请求位写入者未定位。**如果疲惫稳定触发原版换区**，则 v55/v56/v63 已实机 PASS 的**原生疲惫放大**（只改 `0xBD260` 入参 delta、零游戏内存写入、跨怪通用、游戏自己走状态机）就能**间接触发换区** —— 正好满足用户当初「不需要动画演出，强制让一个怪换区」的需求，且不违反零写入纪律。
