## 1 · v57 改动一：W1 覆盖全部主轨抽选（P53 结构性缺口）

P53 实测：`s2=5 / sv2=0 / wt=0` ⇒ v50~v56 的 `rise_weight_pick()` **只在
`REP_N`（prev 命中 → 否决重抽）分支**执行，绝大多数正常抽选仍走 GU 原版权重。

v57 在 `h_matcher` 的 `!repeat` 分支（正常抽选）也调用它：

```rust
if W1_ALL == 1 && GATE_LIVE == 1 && WALL_OK < MAX_WALL_OK
   && sw == 100 && n >= 4 {
    let p5a = a4 + f*7 + WALL_N*13 + 37  (mod 100);
    let (ap, awm, awk) = rise_weight_pick(&cs, n, s, vd, st3, p5a);
    // b_off / nr 范围 / adiff / opcode 全套校验
    if 全部通过 { out_r = anr; ... WALL_OK += 1; W3_N/W4_N/WT_N 按形状累加 }
}
// 任一失败：out_r 保持 r，push_prev 记录原签名，行为与 v38 完全一致
```

**安全护栏**：
- 仅在既有 `main_track`（`op==0x02 && mode==1 && sub==0`）内生效，副轨不干预
- `sw==100`（合法权重和，P37 实机 24/24）与 `n>=4` 才尝试
- 复用 REP 分支的完整 `b_off<=2 / nr∈(0,256] / adiff<=2 / opcode` 校验
- `rise_weight_pick` 本身在合格 case < 3 时返回 −1 ⇒ 原样回退
- `MAX_WALL_OK=12000` 熔断；`WALL_N / WALL_OK / DRAIN_DONE` 累计状态**不随 epoch 重置**
- 成功后 `push_prev` 记录**实际执行**的签名，保证防复读表语义正确

**新增统计**：S 行 `wall`（全抽选尝试）/ `wnok`（成功应用）；
`w3/w4/wt` 现在统计「所有抽选的形状使用次数」，不再是仅重抽。

## 4 · 边界与风险

1. **尚未实机**。A 改动了抽选主干：现在每次主轨抽选都可能被 Rise 形状替换，
   影响面远大于 v50~v56（后者只在防复读重抽时介入）。**必须跑一场验收**：
   重点看动作多样性、连段完整性、有无异常动作或卡住。
2. `P36` 曾标注「无实机证据证明段内 `sub` 变化不经过 `op02/mode==1`」——
   全抽选会放大这个待补项的潜在影响。若出现连段异常，优先把 `W1_ALL` 置 0
   回退到「仅重抽」，并考虑增加段内门控。
3. 发布版**不再强制疲惫**，疲惫形状 `wt` 只在自然疲惫窗口出现；
   判读脚本对该项标 SKIP 而非 FAIL。
4. `p+0x41` 存疑、`t508` 恢复值来源未定案、P33 闪退未归因——均不影响本版功能。
5. W2 距离档、`_IsActionEnd` 门控、12 处境 Hub 仍未实现；
   其中距离档需要先做只读探针才能精确对齐（不需要新增 hook）。
