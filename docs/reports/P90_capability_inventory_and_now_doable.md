## 2 · 能做但还没实现（4 项）

### 2.1 P89① 疲惫形状覆盖率改进 —— ✅ 现在能写码，成本最低
- **问题**：代码已实现（`lib.rs:1023/1536/1592` 的 `BAND_SHAPE` tired 五档 + `SHAPE_T3`），但 `WT_N` 实机计数 **P70 `wt=7` / P79 `wt=1`**，而 W1 全场 `wall=116/wnok=63` ⇒ 疲惫形状两场只用了 7 次与 1 次。
- **疑因**：W1 门槛 `sw==100 && n>=3 && main_track`（`:2163`）；**W4 在 `hub==3`（换区）直接 `return(-1,0,0)` 不套形状**（`:1605`），恰与 P87 重判的疲惫窗 7 次换区信号重合；疲惫窗主轨抽选本身稀疏。
- **改动**：编译期开关 + 放开上述条件，零新增 hook / 零写入 / 跨怪通用。
- **边界**：GU 只有一张 `*_cmdtbl`，**换不了候选集合**，只能压权重 ⇒ 机制级近似非 1:1；低熵与 P87 FNV0 让位在同一处冲突，**必须联合设计**。

### 2.2 P87① 纯只读 FNV0 探针 —— ✅ 现在能写码，且是后续所有推断的前置
- **要测**：疲惫态 / 非疲惫态各自 `sig==FNV0`（空签名 case）命中次数、**命中后到下一动作开始的帧差分布**、该段 `+0x508/+0x506` 耐力百分比、`dc=mon+0x73DC`、`t505`、`area/req`、段内动作数。
- **判据**：是否存在「耐力 ≤20~30% + 换区/脱战」重合且持续 ≥300 帧的低动作段；并用 `area` 变化 + 主怪是否在场 + BEAT 全量交叉排除「赶路 / 离场」伪空档。
- **成本**：加几行统计输出 + 把 `+0x508/+0x506` 读取移出 `DRAIN_ENABLE` 分支（`:2421`，与 P80 stance 修复同类）；**不动行为、不动开关、零新增 hook**。
- **为何必须先做**：P86 三风险全在 —— 「空签名 = 可攻击待机」仅推断、派发器每帧调用可能只有 1 帧、`sig` 非唯一 ID 会污染 `prev_hit_d` 判重。

### 2.3 P87② 疲惫态让位权重槽 —— ⚠️ 现在只能写骨架，不能定参数 / 不能验收
- 技术通道**全已具备**：`dc/t505` 在 QX 行（`:2361`）、耐力在 `0xBD260`、换区在 AR 行 `area/req`、FNV0 在 `h_matcher` ⇒ 零新增 hook / 零写入 / 跨怪。
- 门控拟按 Rise 曲线：`(t505>=2 || dc==1) && 耐力% <= StartPoint(20/30) && hub3/hub1` 时放开 `rise_weight_pick` 的 FNV0 排除（`lib.rs:1575`）并给独立权重槽、`>= EndPoint(70/80)` 撤销；`_mapNikuEatSec=20s` 只作护栏与评估基准。
- **阻断**：2.2 未出数据前不知道窗口是否真实存在、多长、是不是进食；FNV0 独立判重 / 每场次数 / 最短间隔护栏也依赖该数据。**现在上线等于赌推断**。
- 另一条边界：让位只能「不打断」GU 原生进食，不能强制触发。

### 2.4 P84 静态数据层改怒时速度 —— 技术上可做，但不属本任务主线
- 单条目补丁 arc 改 `*_dttune` 30 f32 前 3 项，工具链（`arc_tool.py pack --orig`）与 P48/P61 实机经验已有，94 怪可批量。
