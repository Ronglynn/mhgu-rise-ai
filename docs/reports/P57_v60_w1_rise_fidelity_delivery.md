## 2 · W1 内的四项对齐（结构 / 命名 / 约束保持）

1. **形状表换成 Rise 实测**：读 `out/rise_routine_rates.json` 的 15 池，每池 `rates` 降序后按 `(state,k)` 求均值并补到和 100 ⇒ `SHAPE_A3/A4/N3/N4/T3`（保持 `SHAPE_*` 命名与 `[u32;4]` 类型）。
   - anger k3 `[55,25,20]` / k4 `[40,25,20,15]`
   - normal k3 `[47,28,25]` / k4 `[41,25,22,12]`
   - tired k3 `[60,30,10]`（熵拟合，见 §4）
2. **三状态真正分离**：怒 / 常 / 疲各用自己的形状与 k3:k4 混合比（anger 40:60、normal 60:40、tired 100:0，均为 Rise 池数实测比例）。`W_MIX_PCT` 保留为 normal 比值（61→60），新增同族 `W_MIX_ANGER_PCT=40`。`wm/wk` 语义、`w3/w4/wt` 统计、S/V 行格式不变。
3. **护栏 `n>=4 → n>=3`**：Rise 15 池里 10 个是 3-case 池；P56 实机证 `n>=4` 只让 13.5% 抽选进入 W1。`rise_weight_pick()` 内 `m>=3` 仍是硬底线，`sw==100`、全套 `b_off/nr/opcode` 校验、`MAX_WALL_OK` 熔断全部保留。
4. **k 截断归一化**：合格候选 `m` 少于目标 k 时，不再整包退回 GU 原版权重，而是按 m 截断形状前 kk 项并归一化回和 100；`wm` 按实际 kk 重算。

**逐字节不变**：W2 距离档只读探针（Z/ZP/ZS 行、`scan_cases_near`、`ZS` 指针扫描）、疲惫链、6 个 `#[forge::hook]`、`DRAIN_ENABLE=0` / `PROFILE_RELEASE=1` / `W1_ALL=1`、`W2_PROBE=1`、全部自保护与配额、日志行格式、`6_` 与 `load_order`。

## 4 · 与 Rise 的关键差异（简要）

| # | 差异 | 性质 |
|---|---|---|
| 1 | **无 15 张 `(状态×距离)` 独立池表**：GU 只有一批 `op02` 加权块，v60 用「按原权重降序取 top-k + Rise 排序形状重分配」结构性近似 | 数据表级 1:1 不可行（P32 M4） |
| 2 | **5 距离档未参与加权**：Rise 是状态×距离共同索引；v60 的 W2 仍只是只读探针，档位加权未实现 | 未完成项 |
| 3 | **疲惫形状是熵拟合不是字面均值**：`[60,30,10]` vs Rise `[55,35,10]`（L1=10）。因形状均值熵 1.3367 高于 Rise 池平均熵 1.2984，沿用 P35 定案使熵落到 1.2955 | 有意取舍 |
| 4 | **anger 混合熵 +0.0437**：按 Rise 字面 k3:k4=2:3 (40:60) 会略高于 Rise 池平均熵；选字面比例而非再拟合 | 有意取舍 |
| 5 | **`_CheckPrevTableInfoList` 是近似**：GU 用 3 项 prev 表 + depth 2/1（P32 M2 收敛），非 Rise 完整表结构 | 机制级近似 |
| 6 | **k 由 GU 池大小截断**：假设 Rise 同样按池内 case 数决定 k，无运行时证据 | 显式假设 |
| 7 | **`_IsActionEnd` 门控 / 12 处境 Hub / 领地争夺 / Timer-Counter 因果**未实现 ⇒ 动作节奏（用户说的「输出窗口」）仍是 GU 原版 | 未完成项 |
| 8 | **界面 / 视觉风格**：本项目无 UI 层，不做任何渲染或资源改动 | 不适用 |
