## 3 · 「W3 似乎让它一直攻击」——归因不成立：W3 一次都没生效

`ge=21 / gs=0 / ek=363` ⇒ **门控从未拦下任何重抽**。根因是 GU 原生时序：

```
END 请求 363 条 / 动作开始 338 条
END → 下一动作开始 p50 = 0 帧，≤3 帧占 70%
```

`w3_gate()` 判 `START_F > END_F` 为动作进行中；但 END 请求与下一动作几乎同帧，重抽发生时 `END_F >= START_F` 恒真 ⇒ `IN_ACTION` 永不成立。**GU 本来就不存在「动作未结束就重抽」的窗口**，W3 没有可拦的对象。这正是 P68 报告预判的「若体感无改善 ⇒ GU 原生 END→提交本就 1 帧，W3 结构性收益有限」。

所以「一直攻击」来自 **GU 原生节奏 + W1/W2 的权重形状**，与 W3 无关。按实机定案，v70 把 `W3_GATE_ENABLE` 置 0 撤回无效门控（代码保留，编译期可再开），因为它不改变任何行为却会误导体感判断。
