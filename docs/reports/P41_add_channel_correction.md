# P41 · 更正：「不打怪跑法无效」是错误结论

日期：2026-11-12 22:23 UTC+8 ｜ 触发：用户质疑「怪物攻击不是会扣自身 stamina 吗？」
裁定：**用户正确，P40 §4–§6 与 P39 判据 A 撤回。**

---

## 1 · 错在哪

P40 用「v48 P30 场 40 条 U 行（≥39 次 add 调用）vs 本场 v51 0 次」推出
「玩家攻击输入可能是打开减气通道的必要条件」，并据此把实机脚本首选跑法改成「正常打怪」。

这个对照**不成立**：v48 那 39+ 次 add 调用不是自然产生的，也不是玩家攻击产生的，
而是**插件一次性强制触发之后**疲惫状态机的连锁。

## 2 · 决定性证据

回退基线 `plug/context_probe/src/lib.rs.v48bak:868-881`：
`force` 条件是 `f>=600 && A_N>=20 && 0<thr<0x4000`，命中后把 `a1` 放大为 `thr+16`。
U 行在 `original!` **之前无条件记录每次调用**，配额 40。

P30 归档 `out/game_p54_lite_20261111_2254_v48_FULL.txt`：

| 时段 | 实测 |
|---|---|
| f<5193（强制前） | **U 行 0 条** ⇒ `0xA30E4` 从未被调用；主怪 17 条 R 行 `ex=[0]`、`amt=[0]` |
| 同期 `BEAT.a` | f=2700 起动作开始，f=5100 已 **28 次**，`sel=10`（玩家在正常打怪） |
| f=5193 | 首条 U 行，`a1=10`、`force=1`、`cnt=0` ⇒ 插件把 amount 放大到 158 |
| f=5604 起 | 39 条真实 U 行，`a1=10/15`、`cnt` 0→215、`thr 142→190→237`、`proc 0→2` |
| f=5700 起 | `ex` 首次非零（15→25→40→…），`d5` 出现 35 个不同值 |

本场 v51 快照 `out/game_p54_lite_20261112_2213_v51_LIVEPAUSE.txt`：
89 次动作开始、`gac=0`、`ex=[0]`、`amt=[0]`、`d5=[0]` —— 与 **v48 强制前**逐项一致。

⇒ `add=0 / ex=0` 是**自然静默态**，与打不打怪、与怪种、与暂停都无关。
本场数据**不能**否定「不打怪让怪自己动」这个对照实验，反而与 P20 的定案自洽。

## 3 · 真正的错误：探针挂错了层

P29 `out/P29_tired_trigger_chain_and_next_round.md:99-106` 的链条是：

```
0x9DB54 / 0x9DBE4 : ldrh r1,[act+0x4D8]; add r1,r1,r3; strh  ← 每动作累加 amount
0x98A60 → 0x9A34C 状态更新总入口
    └ 0x9A470 : amount = act+0x4D8 → bl 0xA30E4 (EXHAUST add)  ★
0xA30E4 : counter(act+0x5D82) += amount; counter>=thr → ret 1 → grow → tired FSM
```

`0xA30E4` 是**减气蓄积 counter 的累加入口 / 阈值判定**，不是「每动作扣当前 stamina」的通道。
它只在状态块更新走到减气分支、且有有效 amount 时才被调用。P30 证明：
强制触发让疲惫状态机激活后，游戏才开始按 10/15 点逐动作累加。

P20 §3/§4 早已写明：「前 7 轮一直在追状态字 / 疲惫时长 / 函数入口，
而没有追**被轮询的当前耐力值**」「共同问题：都在改触发的输入或结果的标志，
没有改被轮询的当前耐力值」。v48~v51 仍然盯在 `ex`（蓄积量）与 `0xA30E4`（它的累加器）上，
**这正是 P20 批评的那个层级错误**。用户 21:40 问「疲劳应该关注怪物 stamina 值的变化对吗」，
方向是对的，我当时只把 `s3f/f5c` 否定掉，没有把探针移到正确的层。

另需区分证据等级：P20 的 `_subStaminaPoint`（每动作扣自身耐力）是 **Rise 侧 RSZ 实证**
（em001 296 动作 46 个非零、em002 393 动作 98 个非零）；GU 侧 `stamina_point` /
`StaminaSubRate` 是**同构推断**，`docs/spec-crossgame/monster-gu.md:228` 标为
「GU-unconfirmed」。所以「GU 怪攻击一定走 `0xA30E4`」从来不是定案。

## 5 · 下一步（v52 方向，按风险排序）

1. **离线定位「当前耐力值」字段（零风险、不用实机）**：从 `cEmStaminaData::cStaminaLev`、
   `mParam.stamina_point @0x1eb8d0`、`0x9DBE4` 的 `strh` 目标反查哪个偏移是被轮询的当前值；
   P38 已否定 `mon+0xCAC0→+0x3F/+0x5C`（s3f 恒 0、f5c 恒 f32 30.0），不要再试。
2. **零新增 hook 探针**：在已装的 `h_start_40`（`0xAFF40` 动作开始）里做纯只读快照，
   读 `act+0x4D8` 与候选当前耐力字段；R 行 150/30 帧快照采不到瞬时 amount（两场 amt 恒 0），
   动作开始 hook 的时机更接近写入点。
3. **必要时新增 hook**：`0x9DB54` / `0x9DBE4`（P29 §2.2 每动作累加）或 `0x9A470`。
   需先实机核对运行时首字（IPS32 补丁使 176 函数进解释器模式，`E28FFxxx` 不可 hook），
   且会突破「5 hook / 零新增」纪律，须单独评估。

**跑法结论**：用户原计划「不打怪、让怪自己动」**有效**，脚本已改回，照原计划即可。
但当前 v51 探针看不到这一层的扣减；要回答「GU 每动作到底扣多少 stamina」，
需要上面的 v52 换层，不是换怪或换打法。
